## 目标

把"阶段摘要（`core_summaries`）注入"从**无条件注入**改为**自适应注入**：仅当客户端自带上下文 ≤1 条（非 system 消息）时才注入，>1 条时跳过。原理与现有 `INJECT_DB_HISTORY=auto`（gateway.py:1640-1652）完全对称。仅改 Web 渠道 `_inject_context`，TG/QQ 渠道（server.py `_build_channel_context`）保持不变。

## 新开关语义

| `INJECT_CORE_SUMMARIES` | 行为 |
|---|---|
| `auto`（默认） | 客户端 user/assistant 消息 ≤1 条 → 注入；>1 条 → 跳过 |
| `always` | 总是注入（= 现状） |
| `never` | 从不注入 |

阈值与 `INJECT_DB_HISTORY` 一致：`_client_msg_count > 1` 即跳过。

## 改动点（均在 `C:\Users\钟梓昕\Desktop\rikkahub\新网关\gateway.py` 的 `_inject_context`）

### 1. 前移消息条数计算（共享计数，DRY）

当前 `_client_msg_count` 在 1642-1645 计算，但阶段总结获取在 1588（更靠前）。把条数计算**提到阶段总结块之前**（1587 之后、1588 之前），DB 历史块复用该值并删掉 1642-1645 的重复计算：

```python
# 自适应注入共用：客户端自带非 system 消息条数
_client_msg_count = sum(
    1 for m in req_data.get("messages", [])
    if m.get("role") in ("user", "assistant")
)
```

### 2. 阶段总结块加自适应判断（1588-1600 改造）

照搬 `INJECT_DB_HISTORY` 模式：跳过时**不查 DB、不读/填 TTL 缓存**，`core_summaries` 直接置占位 `"无长期记忆"`：

```python
# 阶段总结自适应注入（与 INJECT_DB_HISTORY 同模式）
# 📦 客户端已自带上下文（非 system 消息 >1）时跳过，维持 stable_system 前缀稳定。
#    由环境变量 INJECT_CORE_SUMMARIES 控制：auto=自适应（默认）、always=总是注入、never=从不注入。
_inject_core_summaries_mode = os.environ.get("INJECT_CORE_SUMMARIES", "auto").strip().lower()
_skip_core_summaries = (
    _inject_core_summaries_mode == "never"
    or (_inject_core_summaries_mode == "auto" and _client_msg_count > 1)
)
core_summaries = "无长期记忆"
if not _skip_core_summaries:
    # 原 TTL 缓存 + DB 查询逻辑（保持不变）
    core_summaries = _stable_cached("core_summaries", _CORE_SUMMARIES_TTL)
    if core_summaries is not None:
        _log(f"📦 [Cache] core_summaries 命中 TTL 缓存（{_CORE_SUMMARIES_TTL}s）")
    else:
        core_summaries = "无长期记忆"
        try:
            sr = await asyncio.to_thread(lambda: sb.table("memories").select("content").eq("tags", "Core_Cognition").order("created_at", desc=True).limit(3).execute())
            if sr and sr.data:
                core_summaries = "\n".join([f"- {s['content']}" for s in sr.data])
        except Exception:
            pass
        _stable_set("core_summaries", core_summaries)
else:
    if _inject_core_summaries_mode == "auto" and _client_msg_count > 1:
        _log(f"📦 [Cache] 客户端已带 {_client_msg_count} 条历史消息，跳过阶段总结注入（维持缓存前缀稳定）")
```

### 3. stable_parts 条件拼装（1707-1712）

跳过时不追加阶段总结标签，使 `stable_system` 在多轮间统一为"无摘要"版本：

```python
stable_parts = []

stable_parts.append(f"【{user_name}的核心画像】:\n{user_prof}")

```

### 4. DB 历史块去重复计算（1640-1649）

删掉 1642-1645 的 `_client_msg_count` 计算（已前移），其余判断逻辑不变。确保 1651 引用 `_client_msg_count` 仍可用。

### 5. 完成日志修正（1788）

`总结{len(core_summaries)}字` 在跳过时为占位 6 字会误导，改为显式标注跳过：

## 不改的部分

- **server.py `_build_channel_context`**（TG/QQ 渠道）：保持无条件注入阶段总结。理由：TG/QQ 是单条 query 进入、无"客户端自带多轮上下文"语义，auto 判断无意义；与 `INJECT_DB_HISTORY` 自适应当初只做 Web 渠道保持对称。

## prompt cache 影响说明

阶段摘要在 `stable_system` 前缀**内部**（区别于 DB 历史注入在前缀外部）。但客户端单调累积消息时，"≤1 条"只发生在每个新对话首轮（首轮本就无可命中缓存），第 2 轮起均 >1 → `stable_system` 统一为无摘要版本，多轮间前缀反而更稳定。净影响中性偏正向，与 DB 历史注入"客户端有上下文就别注入、保护前缀"的意图一致。风险：客户端非单调累积（时而 1 条时而多条）时前缀横跳，正常客户端不会如此。
